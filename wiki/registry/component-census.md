# How to read this

The lists below are **generated**, not written. `pnpm sync:readme` derives them from the
named exports in `src/index.ts` and rewrites the regions between the
`<!-- BEGIN:* -->` / `<!-- END:* -->` markers.

**Do not edit inside the markers by hand.** The `validateArchitectureCensus` gate compares
both the headline counts and the full name lists against `parseIndexExports()` and fails
the build on any drift. The gate exists because the counts once said 36/12 while the code
exported 88/14 — the README, the badges, and the architecture doc all disagreed with
reality for a release cycle.

A component is a primitive or a composite by the
[mechanical taxonomy rule](/architecture/taxonomy-rule.md), never by domain feeling.

# Why export counts differ from folder counts

Counting `src/components/primitives/*/` directories gives a different number than counting
named exports, and both are correct answers to different questions.

| Question | Count from |
| --- | --- |
| How many component folders exist? | `find src/components/<layer> -maxdepth 1 -type d` |
| How many names does the barrel export? | `src/index.ts` — what this census measures |

A composite family such as `ChatMessage` lives in **one** folder but contributes many flat
named exports (`ChatMessageRoot`, `ChatMessageContent`, `ChatMessageToolbar`, the six
`ChatMessageBranch*` subparts, …). Conversely, the [isolated
engines](/architecture/isolated-engines.md) — `Whiteboard`, `Slide`, `SlideDeck` — occupy
folders but are deliberately **excluded** from the barrel and therefore from this census.

Quote the export count when talking about API surface, and the folder count when talking
about maintenance surface. Never present one as the other.
