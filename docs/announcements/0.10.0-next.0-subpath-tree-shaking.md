# `@theokit/ui@0.10.0-next.0` — Subpath imports now tree-shake (no migration required to benefit)

> **TL;DR** — `@theokit/ui@0.10.0-next.0` ships a build-pipeline fix that finally makes Vite/Rollup tree-shake the library properly. The `@theokit/ui` chunk in the TheoCloud dashboard dropped from **36.96 KB brotli → 10.96 KB brotli (−70%)** by installing the new version. **Zero breaking change.** Switching to subpath imports (`@theokit/ui/alert`) is optional and yields additional savings on top.

---

## What changed

Until 0.10, the ~100 subpath exports declared in `package.json#exports` (`./alert`, `./button`, `./table`, …) all pointed at the same `dist/index.js` (the full 417 KB barrel). `import { Alert } from "@theokit/ui/alert"` resolved **byte-identical** to `import { Alert } from "@theokit/ui"`. The subpath form was cosmetic.

`0.10.0-next.0` fixes this:

- `tsup` now auto-globs primitive + composite folders and emits **per-component dist files** (`dist/primitives/alert/index.js`, `dist/composites/code-block/index.js`, etc.)
- `splitting: true` deduplicates shared code (`cn`, theme helpers, forwardRef wrappers, lucide imports) into ~119 shared chunks
- The barrel `dist/index.js` shrank from **417 KB → 49 KB** because all component code now lives in those shared chunks
- `package.json#exports` was rewritten so every per-component subpath points at its own dist file (no more cosmetic aliases)
- `import { X } from "@theokit/ui"` (barrel) **still works** — additive, non-breaking migration shape (same as `@mui/material`)

---

## Action required: **none**. Just bump the version.

```diff
- "@theokit/ui": "0.9.0-next.0"
+ "@theokit/ui": "0.10.0-next.0"
```

Run your install command and rebuild. You'll see the `@theokit/ui` chunk in your build report shrink immediately. The barrel-shaped imports you already have benefit from tree-shaking now because the post-0.10 barrel is structured as per-component re-exports from shared chunks — your bundler can drop individual chunks per actual usage.

---

## Optional: switch to subpath imports for additional savings

```diff
- import { Card, Button, Alert } from "@theokit/ui";
+ import { Card } from "@theokit/ui/card";
+ import { Button } from "@theokit/ui/button";
+ import { Alert } from "@theokit/ui/alert";
```

This is a **gradual, opt-in** migration — change imports file by file, no rush. The barrel form keeps working for whatever you don't migrate.

CSS, themes, and isolated engines stay barrel-imported:

```ts
import { ThemeProvider, violetForge } from "@theokit/ui";
import "@theokit/ui/styles.css";
import { Whiteboard } from "@theokit/ui/whiteboard";  // unchanged
import { Slide } from "@theokit/ui/slide";            // unchanged
```

## Bundle delta — measured, not estimated

Source: TheoCloud dashboard (~30 of 116 components imported, `size-limit` brotli report).

| Metric | 0.9.0-next.0 | 0.10.0-next.0 | Δ |
|---|---|---|---|
| `@theokit/ui` chunk | 36.96 KB brotli | 10.96 KB brotli | **−26.00 KB (−70.3%)** |
| TOTAL initial JS | 176.27 KB brotli | 134.68 KB brotli | −41.59 KB (−23.6%) |

The `@theokit/ui` per-chunk size-limit (50 KB) now passes with **39 KB headroom** (was 13 KB). Total hard gate (240 KB) passes with **105 KB headroom** (was 64 KB).

Savings on your app will vary with how many components you import. Apps using more components see proportionally smaller deltas; apps using fewer see larger ones.

## What didn't change

- Component APIs (every `<Alert>`, `<Table>`, `<CopyButton>`, etc. has the same props as 0.9.0)
- CSS — `dist/styles.css` + `dist/components.css` are still barrel-level (per-component CSS would create a network waterfall worse than the JS savings)
- Theme API (`<ThemeProvider>`, `violetForge`, `defineTheme`, `useDensity`, etc.)
- Isolated engines (Whiteboard / Slide / SlideDeck / Slide plugins) — they already had per-component dist
- React peer range (`>=18.2.0 <20`) — works with 18.x and 19.x
- shadcn CLI registry — same `npx shadcn@latest add` URLs

---

## Heads-up: per-component `.d.ts` types resolve via the barrel

Generating per-component `.d.ts` files for all 114 entries OOMed tsup's worker pool (`ERR_WORKER_OUT_OF_MEMORY`) and `--max-old-space-size` doesn't propagate to worker threads. As a trade-off, per-component subpaths point their `types` field at the barrel `dist/index.d.ts`. **TypeScript still resolves `import { Alert } from "@theokit/ui/alert"` correctly** because `Alert` is exported from the barrel `.d.ts` too. The JS dist (where tree-shaking matters) is per-component and small.

Practical impact: your editor / `tsc` will pull in the full type graph regardless of which subpath you import. Build-time tree-shaking is unaffected (Vite/Rollup work on JS, not `.d.ts`).

## Questions?

- **"Will my existing imports break?"** No. Zero breaking change. The barrel keeps working.
- **"Do I need to migrate?"** No. The bump alone gave the canary consumer −26 KB brotli. Migration to subpath form is opt-in for more savings.
- **"What about types?"** TypeScript resolves both `@theokit/ui` and `@theokit/ui/<x>` correctly. No `tsconfig.json` changes needed.
- **"Why didn't this work before 0.10?"** The barrel `dist/index.js` re-exported all 116 components in one file with `forwardRef(...)` call expressions and `Object.assign(Root, {...})` compound components. Rollup's conservative side-effect analysis bailed out and shipped the entire 240 KB minified barrel regardless of how few imports the consumer used. The fix moves component code into shared chunks the bundler can drop individually.
- **"Will there be more changes like this?"** No more pipeline changes planned. Future releases add components (Brief #5, #6, …) without breaking the build shape.
