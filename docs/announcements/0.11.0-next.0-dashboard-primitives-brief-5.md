# `@theokit/ui@0.11.0-next.0` — 5 new components, zero breaking change

> **TL;DR** — Brief #5 ships 5 new components in `@theokit/ui@0.11.0-next.0`: `PinInput`, `DataTable`, `PageShell` (the 3 closing the TheoCloud Deep Review findings) + `DropdownMenu` and `ActionBar` (pre-reqs the brief assumed existed). **Zero breaking change**, **zero new peer-deps**, **+0.02 KB brotli** measured on the TheoCloud canary (effectively zero impact when not yet imported — confirming Brief #4's tree-shaking still works).

---

## What changed

5 new components, all closing measured findings from the TheoCloud dashboard's design review:

| Component | Type | Closes | What it gives you |
|---|---|---|---|
| **`PinInput`** | primitive | Deep Review § 2.12 P2 | 6-box OTP/code input with auto-advance focus, paste, mask, error state — the standard pattern from Apple ID / Stripe / Clerk / GitHub two-factor |
| **`DataTable`** | composite | Top-5 fix #2 + § 2.2 + § 2.4 P1 | Generic sortable + sticky + expandable + row-actions + paginated table over the existing `<Table>` primitive |
| **`PageShell`** | composite | CC-3 indirect | Page-level scaffold that owns the title + ActionBar + state machine (loading > error > empty > children), dedupes ~20 LOC × 13 dashboard pages |
| **`DropdownMenu`** | primitive (pre-req) | — | Wrapper over `@radix-ui/react-dropdown-menu` (already a bundled dep) with design tokens. Consolidates the 5 prior direct-Radix usages |
| **`ActionBar`** | primitive (pre-req) | — | Search input + filter + primary action row. Used standalone or composed inside PageShell |

All 5 ship with curated MDX docs on `docs.usetheo.dev/theoui` with **18 interactive `<ComponentPreview>` blocks** — type in the search, click the menu, watch the loading skeleton, etc.

## Quick reference for each new component

### `<PinInput>` — OTP / verification code input

```tsx
import { PinInput } from "@theokit/ui";

const [code, setCode] = useState("");

<PinInput
  length={6}
  value={code}
  onChange={setCode}
  onComplete={(v) => verify(v)}
  inputMode="numeric"
  aria-label="Verification code"
/>;
```

Behavior: auto-advance focus on input, paste fills all slots (whitespace stripped, non-digits stripped in numeric mode), backspace clears + moves focus back, arrow keys navigate.

Opt-in props: `mask` (renders bullets), `error` (destructive border), `disabled`, `autoFocus`, `size: "sm" | "md" | "lg"`, `inputMode: "numeric" | "alphanumeric"`.

### `<DataTable>` — sortable + expandable + paginated table

```tsx
import { DataTable, DropdownMenu, type DataTableColumn } from "@theokit/ui";

interface Domain { id: string; name: string; status: "active" | "pending" | "failed"; }

const columns: DataTableColumn<Domain>[] = [
  { key: "name", label: "Domain", sortable: true },
  { key: "status", label: "Status", sortable: true },
];

<DataTable<Domain>
  columns={columns}
  data={domains}
  rowKey={(d) => d.id}
  expandable={(d) => d.status === "pending" ? <DnsRecords domain={d} /> : null}
  rowActions={(d) => (
    <>
      <DropdownMenu.Item onSelect={() => editDomain(d)}>Edit</DropdownMenu.Item>
      <DropdownMenu.Item onSelect={() => deleteDomain(d)}>Delete</DropdownMenu.Item>
    </>
  )}
  pagination={{ pageSize: 10 }}
/>;
```

- **Sort + pagination support both controlled and uncontrolled modes** (pass `onSortChange` / `pagination.onPageChange` to switch).
- **Expandable rows**: multi-row by default, opt-in single-row via `expandMode="single"`.
- **Loading state**: renders 5 skeleton rows. **Empty state**: defaults to `<EmptyState>` or pass `emptyState` for custom.

### `<PageShell>` — page-level scaffold

```tsx
import { PageShell } from "@theokit/ui";

<PageShell
  title="Domains"
  description="Custom domains and DNS verification."
  search={{ placeholder: "Search…", value: q, onChange: setQ }}
  primaryAction={{ label: "Add domain", icon: Plus, onClick: openModal }}
  loading={isLoading}
  error={error ? { message: error.message, onRetry: refetch } : undefined}
  empty={data?.length === 0 ? { title: "No domains yet" } : undefined}
>
  <DataTable columns={columns} data={data} rowKey={(d) => d.id} />
</PageShell>;
```

- **State precedence is strict**: `loading > error > empty > children`. When multiple are set, only the highest renders.
- **PageShell does NOT manage `document.title`** (deliberate scope choice — ADR `page-shell-composite-pattern`). Wire your own hook via `onTitleChange?` callback:

```tsx
const setBrowserTitle = useSetPageTitle();

<PageShell title="Domains" onTitleChange={setBrowserTitle}>…</PageShell>
```

- **Loading default is a centered spinner Card**. For per-page skeletons, pass `loadingNode={<YourSkeleton />}`.

### `<DropdownMenu>` — accessible menu primitive

```tsx
import { DropdownMenu } from "@theokit/ui";

<DropdownMenu>
  <DropdownMenu.Trigger>Actions</DropdownMenu.Trigger>
  <DropdownMenu.Content>
    <DropdownMenu.Label>Project</DropdownMenu.Label>
    <DropdownMenu.Item onSelect={edit}>Edit</DropdownMenu.Item>
    <DropdownMenu.Item onSelect={duplicate}>Duplicate</DropdownMenu.Item>
    <DropdownMenu.Separator />
    <DropdownMenu.Item onSelect={destroy}>Delete</DropdownMenu.Item>
  </DropdownMenu.Content>
</DropdownMenu>;
```

Sub-components: `Trigger`, `Content`, `Item`, `CheckboxItem`, `RadioItem`, `Label`, `Separator`, `Shortcut`, `Group`, `Sub`, `SubTrigger`, `SubContent`, `RadioGroup`.

Internally wraps `@radix-ui/react-dropdown-menu` (already in your `node_modules` — no new peer-dep). Consolidates the 5 prior direct-Radix usages in `model-selector`, `intent-selector`, `agent-profile`, `theme-switcher`, and `theo-code-shell` — they'll migrate to this wrapper in a follow-up cleanup PR (additive, non-breaking).

### `<ActionBar>` — page-top action strip

```tsx
import { ActionBar } from "@theokit/ui";
import { Plus } from "lucide-react";

<ActionBar
  search={{ placeholder: "Search projects…", value: q, onChange: setQ }}
  onFilterClick={openFilters}
  primaryAction={{
    label: "New project",
    icon: Plus,
    onClick: openCreateModal,
  }}
/>;
```

Returns `null` when no slot is provided — won't render an empty bar. Primary action supports `loading: boolean` with a spinner.

## ADR — for the curious

`PageShell` scope was narrowed during the edge-case review: the library does **NOT** manage `document.title`. Different apps use Next.js `<Head>`, react-helmet, custom hooks, etc. — picking winners is wrong layer.

Read the ADR at:
[`.claude/knowledge-base/decisions/page-shell-composite-pattern.md`](https://github.com/usetheodev/theo-ui/blob/main/.claude/knowledge-base/decisions/page-shell-composite-pattern.md)

## Questions?

- **"Will my existing imports break?"** No. Zero breaking change.
- **"Do I have to migrate anything?"** No. Bump the version, rebuild. Migrate to the new primitives when your team plans its next feature work.
